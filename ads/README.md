# Ads console (ads.edgebourne.com)

Private dashboard for the Edge Bourne Meta ads: new leads arrive by webhook, get emailed to
the team, and are worked in an inbox (stage, owner, notes); the Performance page shows spend,
leads and cost per lead from Meta next to what the team did with those leads. Plan and phases:
`docs/PLAN.md`. Meta app setup: `docs/META-APP-SETUP.md`.

Stack: Flask + gunicorn, vanilla JS/CSS (no build step). It runs inside the EdgeBourne
Compose stack:

| Piece | Where |
|---|---|
| `ads-backend` service (`edgebourne-ads-backend`) | `ads/backend`, built by the root `docker-compose.yml` |
| Database `ebads` | the EdgeBourne Postgres; created by the backend on first start, migrations in `backend/migrations/` |
| Static files + routing for `ads.*` | the EdgeBourne nginx container, `ads/nginx/ads.conf` mounted as `conf.d/zz-ads.conf` by `docker-compose.proxy.yml` and `docker-compose.dev.yml` |
| TLS | the shared host proxy; `install.sh` Update adds `ads.<domain>` to the certificate once its DNS record points at the server |

Configuration comes from the root `.env`: the session/encryption key is derived from
`SECRET_KEY`, the address is `https://ads.$DOMAIN`, and `ADS_ADMIN_INITIAL_PASSWORD`
(generated by the installer) only creates the first admin. Meta and SMTP keys are entered in
Settings and stored encrypted; they never go in `.env`. Lead alerts use the website's mail
settings (Admin → Email, read from its database by `backend/site_mail.py`) unless a
different mailbox is entered in the console's Settings → Email. Changing `SECRET_KEY` makes them
unreadable and they must be re-entered.

## Run locally

```bash
# in the repo root; add ADS_ADMIN_INITIAL_PASSWORD=<anything> to .env first
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d --build
open http://ads.localhost:8090
docker exec edgebourne-ads-backend python dev_seed.py   # optional sample data (local only)
```

Tests: `docker exec -e WORKERS_ENABLED=0 edgebourne-ads-backend python -m unittest discover -s tests -v`.
Screenshots (light/dark, desktop/phone, fails on console errors): `node ads/qa/shots.cjs <out-dir>`.

## How it works

- `POST /webhooks/meta`: Meta's leadgen ping, signature-checked (`X-Hub-Signature-256`, App
  secret). Stored in `webhook_events`; a background job (gunicorn `post_fork`, Postgres
  advisory lock) fetches the lead with the Page token, saves it and emails admins plus
  teammates assigned to the lead's campaign. The same job syncs ads and daily insights hourly.
- Roles: admins see everything; team members see leads and results of their campaigns only.
- Every change goes to the `activity` table (Settings → Activity).
- The CSP forbids inline scripts and styles: use classes in `frontend/css/app.css`, and set
  computed sizes from JS through CSSOM (`el.style.width = …`), never a `style="…"` attribute.
- nginx resolves `ads-backend` per request, so the main site still starts when this service
  is down.

## Pages

| Page | What it's for |
|---|---|
| Home | Needs attention (Meta-stopped ads, ads on but never shown, leads waiting > 1 h, Claude's pending proposals, spending limit, Mac offline), today's spend so far (live, cached 5 min), yesterday, last 7 days, newest leads, Claude, recent changes |
| Leads | Inbox with the lead clock, stages, owner, notes |
| Ads | Campaign → ad set → ad cards with media, results for 7/14/30 complete days, on/off switches, budget editing |
| Ad (`ad.html?id=`) | Tabs. **Overview**: Meta's real previews per placement (`/{ad}/previews`, iframe from facebook.com), results, words, where it runs (with Meta's audience-size estimate), pending proposals, leads. **Polish**: the preset audit passes and "Make a new version". **Audience**: spend and leads by placement, age, gender, device, region, hour. **Video**: watch funnel, hook and hold rate, Meta's quality / engagement / conversion rankings, frequency, CPM. **Comments** on the ad's post. **History**: dashboard changes and decided proposals |
| New ad | Copies an existing ad's story spec (Page, Instagram identity, lead-form button), new image or video (upload or library) and words; created **off** |
| Performance | Totals, charts, per-ad table |
| Desk / Research | Directions for Claude; research adds Ad Library search links |

Polish (`backend/polish.py`): eleven preset passes (hook, headline, primary text, call to
action, message & intent, visual design, AI signal, placements, motion & sound, policy,
performance), each with the exact checks that took N1–N5 from first draft to approved, plus
presets (full, words only, design only, quick). A run is a Desk task of kind `polish` whose
`options` carry the pass definitions; Claude posts a scorecard (`desk scorecard`: 1–5 per
pass with findings and fixes) and copy variants as `creative` proposals with a payload
(starting ad + words + `media: same`). Approving one creates that ad, switched off.
"Make a new version" is kind `render`: the bridge allows the render pipeline (node, ffmpeg,
edits under `creatives/`) for that kind only; Claude uploads the result with `desk upload`
and proposes it as a new ad.

On-demand Meta reads (`backend/insights_api.py`, cached in `meta_cache`): breakdowns,
diagnostics (rankings), comments (Page token), delivery estimates, account activity.
The hourly sync also stores video funnel numbers per day (`video_3s`, `thruplays`,
`video_p25..p100`, `clicks_all`) and each ad's post id; ads that disappear from Meta are
marked `DELETED` and hidden.

Controls: admins everywhere, teammates on their assigned campaigns. Every write to Meta goes
through `ads_api.py` and lands in `meta_changes` (who, what, old → new, result) plus the
activity log. Budget changes are free with a confirmation that shows dollars, % and a
warning above +20%. Approving a Claude proposal applies `status` and `budget` proposals that
name an exact entity; other kinds are recorded. Uploads: images go to `adimages`, videos to
`advideos` in chunks (memory stays flat); nginx allows 260 MB only on `/api/media/upload`.

Local development uses a fake Graph API (`ads/dev/fake_meta.py`, service `fake-meta` in
`docker-compose.dev.yml`, thumbnails from `ads/dev/media`) so every write can be tried
without touching the real account. Set any value for the System User token in local
Settings; the fake ignores it. `node ads/qa/flows.cjs <out> <image>` runs the controls end to
end (switch, budget, preview, duplicate, upload + new ad, proposal approval).

## AI desk (phase 3)

The **Desk** page (admins) is where Eugene gives Claude directions: a question, a results
review, competitor research or new ad ideas. Claude runs on Eugene's Mac, not on the server:

- `ads/bridge/` is the Mac side. `install.sh` installs the `/ads-desk` skill and the `desk`
  helper into `~/.claude/skills/ads-desk`, keeps the Mac key (created on the Desk page) and an
  optional long-lived Claude token (`claude setup-token`) in the login Keychain, and starts
  `bridge.py` as a LaunchAgent (`com.edgebourne.ads-desk`, logs in `~/Library/Logs/ads-desk`).
- The bridge long-polls `GET /api/agent/wait` (no AI cost while idle) and, per request, runs
  `claude -p "/ads-desk run <id>" --permission-mode dontAsk --allowedTools <read-only list>` in
  the meta-ads workspace. The run can read Meta (MCP read tools), the skill library and the
  web, and talk to the Desk through `desk`; budget, status, publish and delete tools are not
  allowed. Changes come back as proposals (`desk_proposals`), applied in phase 4 only after
  approval.
- `/ads-desk` in Claude Code works the queue by hand (when the Mac bridge is off).
- Agent API (`desk_api.agent_bp`, bearer key, stored hashed): `wait`, `tasks/<id>`, `queue`,
  `tasks/<id>/status|report|proposals`, `snapshot` (performance + inbox lead quality, no
  contact details), `history`. A task the Mac stops reporting on for 30 minutes is marked failed.

## Backups and restore

The installer backs the console's database (`ebads`) up before every Update and every night at
3:20 (`/usr/local/sbin/edgebourne-backup`, files `ads-console-<date>.sql.gz` in the backup
directory, the last 14 kept). A failed dump is not kept and the nightly job reports a failure,
so it never rotates the good backups out. To also copy them off the server, put
`BACKUP_COPY_TO="user@host:/path/"` in `/etc/default/edgebourne-backup` (root needs an SSH key
for that host).

Media uploads are streamed to Meta and deleted, so the database is the only thing to restore.

**Restore** (same server or a new one, with the stack installed and running):

```sh
docker stop edgebourne-ads-backend
docker exec edgebourne-postgres psql -U edgebourne -d postgres -c "DROP DATABASE ebads"
docker exec edgebourne-postgres psql -U edgebourne -d postgres -c "CREATE DATABASE ebads"
gunzip -c ads-console-<date>.sql.gz | docker exec -i edgebourne-postgres psql -U edgebourne -d ebads
docker start edgebourne-ads-backend
```

Messages like `role "ebads_app" does not exist` during the restore are expected on a new server:
roles aren't part of a dump. The backend recreates `ebads_app` and its grants every time it
starts (`db.APP_ROLE_SQL`), so it works once started. Restoring a backup taken before an Update
also brings back that version's data; run the matching code (or Update again) afterwards.
`SECRET_KEY` in `.env` must be the one the backup was made with, or the stored Meta and email
secrets can't be read (paste them again in Settings).

## Design

Tokens at the top of `frontend/css/app.css` (light and dark). The lead clock (time a new lead
has waited: amber under an hour, rust after a day) is the one loud element. Violet is reserved
for anything Claude does (phase 3). Chart colours were checked with the dataviz validator.
Fonts: Bricolage Grotesque (display) and Mulish (UI), self-hosted.
